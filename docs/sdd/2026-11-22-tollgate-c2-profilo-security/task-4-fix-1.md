- **I3 (R-SECURITY-09).** Gli attributi scritti nel codice si chiedono per il cookie che il codice costruisce da sé (`Set-Cookie`, `res.cookie`, `cookies().set` con opzioni proprie). Per il cookie scritto da una libreria di sessioni o di login si chiede solo che il diff non indebolisca le opzioni (`httpOnly: false`, `secure: false`, `sameSite: "none"` senza un motivo scritto accanto). `secure` legato all'ambiente (vero in produzione) vale come dichiarato. `SameSite=None` è ammesso solo con `Secure` e con il motivo scritto accanto. - **m2 (R-SECURITY-08).** «un segreto, un token, una firma o l'hash di un segreto», nel codice che non è di test; una ricerca nel database per token non è un confronto.

Chiudi l'elenco delle impostazioni: la chiave di firma, l'elenco delle origini o dei ruoli ammessi, un interruttore che spegne un controllo.
- **m4 (R-SECURITY-01, R-SECURITY-16).** «Se il diff cambia un file che non è un test né un documento».

- **m8.** R-SECURITY-06 non si applica quando il codice passa la password a un servizio di login che la controlla; R-SECURITY-13 nomina `//host` fra ciò che non è un percorso interno.
