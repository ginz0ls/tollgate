# tollgate C2: profilo `security`

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Il sesto profilo verticale, `security` (autenticazione, autorizzazione, middleware e proxy delle richieste, intestazioni e politiche di sicurezza), con le regole `rules-security` scritte dalle fonti, verificate e approvate dall'utente, gli agenti `implementer-security`, `reviewer-security` e lo specialista finale `final-security` (che C3 userà anche per `ci`). In più, tre scelte dell'utente del 22/11/2026 che valgono per tutto tollgate: il modello di ogni agente (chi trova i bug su Fable, chi scrive o corregge su opus, mai sonnet), la sicurezza fin dal progetto in ogni lavoro (anche fuori dal profilo), e `security` che si accende anche sui file di login che un altro profilo riconosce per contenuto. Una prova reale di un lavoro L2 arriva fino alla revisione finale con `final-security`.

**Architecture:** Il frammento `templates/profiles/security.toml` usa due forme di pattern già esistenti (`**/<cartella>/**` e `**/<nome>` con al più un `*` finale), `[detect] exclude = ["supabase/"]` come `backend` e `frontend`, `[detect] keep_paths = true` (chiave nuova: per questo frammento la regola di I-1 non toglie i percorsi, né le cartelle né i file per nome), `min_level = "L2"`, `final_specialist = "tollgate:final-security"` e una `checklist`. `[detect] content` ha le sole righe di import delle librerie di password e di token. `vertical_for`, `task_routing`, `globs`, `fragments.parse_pattern`, `finalreview`, `reviews` e `dod` non cambiano: lo specialista funziona con il meccanismo di B7. I modelli cambiano nel campo `model` del frontmatter degli agenti, nel suggerimento di `task start` dal giro 4 e nel modello della sessione delle prove. La sicurezza fin dal progetto è testo degli agenti generici (implementatore, revisori, avversari), che arriva alle copie di area con i test di deriva. La prova reale estende `spikes/run-b1-flow.sh` con un caso `security` che riusa i sei passi L2 del caso `database`.

**Tech Stack:** Python ≥ 3.11, solo libreria standard; bash; git; Claude Code (`claude plugin validate --strict`; la prova reale con `claude -p --plugin-dir` solo dal controller). Test con `unittest` tramite `tests/run` (python3.11 e python3).

**Spec:** il progetto di C `docs/superpowers/specs/2026-11-20-tollgate-c-tracciamento-design.md` (l'autorità per C2: sezione 11 per intero, con le scelte dell'utente del 22/11/2026; sezioni 2, 12 e 14); il piano principale di C `docs/superpowers/plans/2026-11-20-tollgate-c-piano-principale.md` (sezione 1, regole 3 e 4; riga C2 della sezione 2; riga «C2 → C3» della sezione 3; sezioni 6, 7 decisione 4, 8); il catalogo `docs/superpowers/specs/2026-10-08-tollgate-profili-verticali.md` (riga `security` di 2, 2.1, 2.3; riga `rules-security` di 4; nota sul prefisso; righe `ci`); il progetto di B `docs/superpowers/specs/2026-10-27-tollgate-b-profili-design.md` (3.4, 4, 5, 11-14); la spec del nucleo `docs/superpowers/specs/2026-10-08-tollgate-nucleo-design.md`, revisione 36 (6.3, 7.1, 7.3, 8.5, 8.7, 10, 11.2, 11.4, 16, 18.4, 20); il modello B7 (`docs/superpowers/plans/2026-11-12-tollgate-b7-profilo-database.md`, `docs/sdd/2026-11-12-tollgate-b7-profilo-database/`); il registro di C1 (`docs/sdd/2026-11-20-tollgate-c1-tracciamento-locale/`).
